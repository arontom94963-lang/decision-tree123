real metrics, computed from the table above

MAE — average marks the prediction is off by, in either direction.
RMSE — same units as MAE, but a handful of badly-missed students weigh more heavily.
R² — the share of the variation in marks the model explains; 1.0 is perfect, 0 is no better than always guessing the average.

    About this notebook

    A few questions people usually ask the first time they see this page.

    Is the model really training in my browser?

    Yes. There's no server behind this page — a small decision-tree-regressor implementation runs in JavaScript, fits itself to the 120 training students, and every number on this page (splits, metrics, predictions) comes out of that run, not a hard-coded value.

    Where did the dataset come from?

    It's synthetic — generated for this notebook so it's free to use and share. Marks are built from study hours, attendance, prior performance, sleep and background, plus some randomness, which is why the tree never gets a perfect score.

    Why a decision tree instead of linear regression?

    A tree can naturally capture "study hours matter a lot below 5, barely above it" style effects without you specifying them. The trade-off is that it can overfit if left too deep — which is exactly why max_depth and min_samples_split are set here.

    Can I use this on my own class's data?

    The structure will work for any table shaped like this one: a handful of numeric and yes/no columns and a numeric target. Swap the CSV, re-run the cells in order, and the same cleaning, encoding and evaluation steps apply.
